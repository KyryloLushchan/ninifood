# NiniFood — доставка домашних обедов в Дананге

## Суть
Каждый день новый обед из 4 блюд. Меню публикуется на неделю вперёд.
Доставка с 14:00 до 16:00 по всему Данангу. Воскресенье — выходной.
Часовой пояс для всех расчётов дат: `Asia/Ho_Chi_Minh` (UTC+7).

## Продукты
- **Разовый заказ** — любой доступный день (Пн–Сб), кроме сегодняшнего. Заказ на завтра можно делать в любое время до 23:59 сегодня.
- **Подписка на 5 дней** — клиент выбирает любые 5 будних дней (Пн–Пт) из дней, на которые опубликовано меню.
- Количество порций — любое (для подписки — одинаковое на все 5 дней).
- Заказ на сегодня через сайт **не принимается**. На сайте строка: «Нужен обед сегодня? Напишите в Telegram до 12:00» со ссылкой.

## Цены (хранятся в БД, таблица settings, не хардкодить)
- Обед: 160 000 ₫
- Подписка 5 дней: 700 000 ₫
- Доставка: 0 ₫ (настраиваемо)
Итог считается **только на сервере** (edge-функция), клиенту не доверяем.

## Стек
- Фронт: чистый HTML + CSS + JavaScript (без фреймворков и сборщиков). Хостинг — GitHub Pages, свой домен.
- Бэкенд: отдельный проект Supabase (Postgres, Auth для админа, Edge Functions на Deno).
- Supabase Storage **не используем**. Скриншот оплаты отправляется сразу в Telegram, в БД сохраняется только `file_id`.
- Telegram-бот + группа Orders.
- Защита формы: Cloudflare Turnstile + проверка гео (только Вьетнам), как в NiniSushi.

## Языки
UA / RU / EN / VI. При первом визите — модальное окно выбора языка (флаги), выбор сохраняется в localStorage. Переключатель в шапке.
Все тексты интерфейса — в одном файле словаря `i18n.js`. Названия и описания блюд — в БД на 4 языках.

## Дизайн
- Стиль «тёплый домашний»: кремовый фон, терракотовый/оранжевый акцент, скруглённые карточки, крупные фото блюд.
- Все цвета, радиусы и шрифты — через CSS-переменные в `:root` (лого появится позже, палитру поменяем).
- Mobile-first.
- Главный акцент — большая кнопка «Заказать на {ближайший доступный день}», например «Заказать на Вт, 27.10». Ближайший доступный день = завтра, если на него есть меню и это не воскресенье, иначе следующий подходящий.
- Пока нет лого и фото — аккуратные плейсхолдеры (текстовый логотип NiniFood, нейтральные заглушки вместо фото).

## Страницы и блоки
`index.html`:
- Шапка: текстовый лого, переключатель языков, ссылки на соцсети.
- Hero: «Домашний обед из 4 блюд каждый день», доставка 14:00–16:00, кнопка-акцент.
- Меню на неделю: вкладки по дням (Пн–Сб), в каждом дне 4 блюда. Дни без меню и сегодняшний день — неактивны.
- Блок «Подписка на 5 дней» с ценой и кнопкой.
- Как это работает (3–4 шага), условия, контакты.
- Строка про заказ на сегодня через Telegram.

`admin.html` — отдельная защищённая страница (Supabase Auth + RLS, функция `is_admin()`), интерфейс на английском.

## Форма заказа
Поля: имя*, Telegram*, телефон*, адрес*, название отеля (необязательно), комментарий.
Выбор: тип (разовый / подписка), день или 5 дней, количество порций.
Оплата: QR или наличные курьеру. При выборе QR показываем QR-картинку и **обязательно** просим прикрепить скриншот оплаты (jpg/png, сжатие на клиенте до ~1280px).
После отправки — экран «Спасибо, заказ принят».
Клиенту никаких уведомлений о смене статуса не шлём.

## Поток заказа
1. Клиент отправляет форму → edge-функция `send-order`.
2. `send-order`: проверяет Turnstile и гео, валидирует даты (не сегодня, не воскресенье, не прошлое, есть меню, для подписки — ровно 5 разных будних дней), пересчитывает сумму по `settings`, сохраняет заказ со статусом `new`.
3. Отправляет в группу Orders сообщение с заказом (+ скриншот через `sendPhoto`, если QR) и кнопками ✅ Одобрить / ❌ Отклонить. `message_id` и `file_id` сохраняются в заказ.
4. Webhook бота (`tg-webhook`): ✅ → статус `confirmed`, ❌ → `cancelled`; сообщение в группе редактируется (статус + кто нажал), кнопки убираются. Нажимать могут только админы из whitelist.
5. В админке: отметка `delivered` по каждому дню доставки.

Статусы заказа: `new` → `confirmed` → `delivered` / `cancelled`.

## Модель данных (черновик)
- `settings` (key, value) — цены, доставка, ссылка на Telegram для заказов на сегодня.
- `menu_dishes` (id, date, position 1–4, name_ua/ru/en/vi, desc_ua/ru/en/vi, photo_url, null допустим).
- `orders` (id, created_at, type `single|subscription`, name, telegram, phone, address, hotel, comment, payment_method `qr|cash`, qty, total, status, tg_message_id, receipt_file_id).
- `order_days` (id, order_id, delivery_date, qty, delivered bool) — по одной строке на каждый день доставки.
- `admins` (user_id) + функция `is_admin()`.
RLS: анонимный клиент читает только `menu_dishes` и публичные `settings`. Запись заказов — только через edge-функцию (service role).

## Админка (admin.html)
- Меню на неделю: редактирование 4 блюд на каждую дату (4 языка, фото-URL позже).
- Цены/настройки.
- Заказы: фильтр по дате доставки и статусу.
- **Список для курьера на выбранную дату**: адрес, отель, имя, телефон, Telegram, порции, способ оплаты (наличные — сумма к получению), комментарий. Кнопка «отметить доставлено».
- Сводка «на дату N порций».

## Правила работы
- Не добавлять функциональность, которой нет в этом файле, без вопроса.
- Секреты (service role key, токен бота, Turnstile secret) — только в секретах Supabase, никогда во фронте и в git.
- Перед крупными изменениями — сначала короткий план, потом код.
- В папке `_ref-ninisushi/` (если есть) лежит код NiniSushi только для справки по паттернам. Его не изменять и в проект не подключать.
