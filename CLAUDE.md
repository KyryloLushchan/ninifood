# NiniFood — доставка домашних обедов в Дананге

## Суть
Каждый день новый обед из 4 блюд. Доставка с 14:00 до 16:00 по всему Данангу, Пн–Сб. Воскресенье — выходной.
Часовой пояс для всех расчётов дат: `Asia/Ho_Chi_Minh` (UTC+7).
Аудитория — туристы и экспаты. Языки: UA / RU / EN / VI.

Целевой адрес — https://ninifoodvn.com (без www; `www` редиректит на него), админка https://ninifoodvn.com/admin. Репозиторий: https://github.com/KyryloLushchan/ninifood. DNS — в GoDaddy (4 A-записи на IP GitHub Pages 185.199.108–111.153 + CNAME `www` → `kyrylolushchan.github.io`).
- **Переключатель адреса — одна строка:** `env: CUSTOM_DOMAIN` в `.github/workflows/deploy.yml`. Пусто → сборка с `NEXT_PUBLIC_BASE_PATH=/ninifood` (github.io/ninifood), CNAME не создаётся. `ninifoodvn.com` → сайт в корне (basePath нет), workflow кладёт `out/CNAME`. Пути к файлам из `public/` (в т.ч. `photo_url` из БД) оборачиваются в `withBasePath` (`src/lib/base-path.ts`).

## Продукты и правила
- **Разовый заказ** — любые дни Пн–Сб из ближайших доступных (`BOOKABLE_DAYS`, сейчас 6), кроме сегодняшнего. Дни выбираются по календарю, независимо от наличия меню: если у дня недели нет блюд в шаблоне `menu_dishes`, день всё равно можно заказать, а в меню показывается «Меню скоро появится». Мультивыбор дней × порции × 170 000 ₫ + доставка 20 000 ₫ за каждый день доставки (не за порцию). При выборе 5+ дней — подсказка перейти на подписку (сравнение итоговых сумм).
- **Подписка** — от 5 дней, любые дни Пн–Сб (не воскресенье) из ближайших 2 недель (до 12); меню на выбранные дни может быть ещё не опубликовано. По умолчанию отмечены ближайшие 5. Обед в подписке = `price_subscription` / 5 (сейчас 150 000 ₫), итого дни × порции × 150 000 ₫ + доставка 20 000 ₫ за каждый день (как у разового). Про выгоду/«−9%»/цену за обед на сайте не пишем (цена видна только в сводке заказа и в подсказке про подписку как итог).
- **Календарь выбора дней** (разовый и подписка, `WeekGrid` в `Order.tsx`): недели Пн–Вс, 7 колонок; воскресенье — серая неактивная ячейка (`DayChip dayOff`, подпись `calendar.dayOff`: вихідний / выходной / day off / nghỉ), не выбирается; сегодняшний день для обычных клиентов — такая же серая ячейка «сьогодні» (`calendar.today`; у VIP сегодня выбирается как обычный день); все доступные невыбранные дни одинаковые (белая ячейка с рамкой, без пунктира «нет меню»; hover только на устройствах с мышью — на тач-экранах залипший hover делал нажатый день серым). Экран заказа: сразу под переключателем «Разовый/Подписка» строка «Порцій на день» + счётчик, дальше выбор дней; нижняя панель — компактный вариант (`BottomBar compact`, `OrderSummary compact`). На 320 px зазор и шрифт подписи уменьшаются, горизонтальной прокрутки нет.
- Порции — любое число ≥ 1 (для подписки одинаково на все дни).
- **Вход по email + паролю (необязательно)** — «Увійти» в шапке и на оформлении, экран `Auth` (4 языка): вход, регистрация (email, пароль ≥ 8, повтор; подтверждение email нет), «Забули пароль?» (на почту 6-значный OTP-код → код + новый пароль на сайте). Всё идёт через `auth-gate`, везде Turnstile. Заказ без входа работает как раньше. Вошедшему: Telegram, телефон и адрес предзаполняются из `customers` (Telegram — обычное поле, клиент вводит его сам), после заказа сервер сохраняет Telegram/телефон/адрес/place в `customers`; «Мої замовлення» — история (номер, дни, сумма, статус); выход. Заказ привязывается к `orders.customer_id`. **Сброс пароля по почте пока выключен** (`auth-gate` отвечает `reset_unavailable`, UI просит написать в Telegram): встроенная почта Supabase на Free не даёт менять шаблон письма (в письме ссылка, а не код) и шлёт только адресам из команды проекта, лимит ~2 письма/час. Включение — раздел «Почта: Resend» ниже.
- **VIP-клиенты** (`vip_customers`: `email` в нижнем регистре, unique, заметка; первый — lushankirill@gmail.com, он же админ): только если клиент **вошёл на сайте под этим email**, ему доступны заказы на любой день, **включая сегодня** в любое время (окно дней начинается с сегодня, воскресенье по-прежнему нельзя; оплата как у всех). Введённый вручную Telegram привилегии не даёт. `send-order` определяет VIP на сервере: `auth.getUser(jwt)` → email → `vip_customers`; фронт знает о VIP через `my_is_vip()` (по email из JWT) только для показа календаря. В Orders-группе у таких заказов «⭐ VIP» в заголовке (`orders.is_vip`). Управление — Админка → Настройки → «VIP-клиенты» (добавить/удалить по email).
- **Персональные скидки по email** (`customer_discounts`: email lowercase unique, `percent` 1–100, `note`, `valid_until` — включительно, null = бессрочно; первая — lykianovib@gmail.com, 30%): действуют только если клиент **вошёл на сайте** под этим email. Скидка — **только на обеды** (разовые и подписка), доставка без скидки. Сумма скидки округляется до 1 000 ₫ **в пользу клиента** (`ceil(обеды × % / 100 / 1000) × 1000`, не больше стоимости обедов; т.е. сумма за обеды — вниз до 1 000), `discountAmount` в `supabase/functions/_shared/discount.ts` и копия `src/lib/pricing.ts`. `send-order` берёт email из `auth.getUser(jwt)`, ищет действующую скидку (valid_until пусто или ≥ сегодня по Дананг-времени), поля формы не влияют; `orders.total` = обеды − скидка + доставка, `discount_percent`/`discount_amount` хранятся в заказе. Сайт знает процент через RPC `my_discount()` (security definer, только authenticated, возвращает лишь процент текущего пользователя; показ — сервер считает сам): в сводке строка «Знижка N%» (`OrderSummary`), пометка «Ваша знижка N%» (`DiscountBadge`) на главной и на оформлении; QR/назначение и «Разом» — с суммой после скидки. Управление — Админка → Настройки → «Персональные скидки» (`DiscountCard.tsx`: список, добавить email/%/до даты/заметка, удалить вторым нажатием).
- Воскресенья недоступны. Заказ на сегодня через сайт **не принимается** (кроме VIP); на сайте про заказ на сегодня ничего не пишем (ни на главной, ни на экране заказа). `settings.telegram_url` остаётся для «Другого способа» оплаты.
- Кнопка hero — «Заказать на {ближайший доступный день}».
- Источник истины по ценам — таблица `settings` в Supabase. Значения в `src/config/site.ts` — только для показа на сайте до подключения бэкенда. Сервер **всегда считает сумму сам**, клиенту не доверяем.

## Форма заказа
Поля: Telegram*, телефон*, адрес*, отель, комментарий. Имени нет. Телефон: префикс `+84` зафиксирован слева внутри поля (`Field prefix`), клиент вводит 9 цифр (`src/lib/phone.ts`: `phoneDigits` — только цифры, убирает ведущий 0 и вставленный +84/84, `formatDigits` → «90 123 45 67»); ровно 9 цифр, иначе `error.phone_invalid`. Хранится как `+84XXXXXXXXX`. Подсказки под полем Telegram нет.
**Автозаполнение браузера** (Checkout): поля внутри одного `<form autoComplete="on">` с `name`: `telegram` (`nickname`), `phone` (`type=tel`, `tel-national`, `inputmode=tel`), `address` (`street-address`). Телефон от автозаполнения/вставки (не набор руками — определяем по `inputType` события, плюс `blur` и `animationstart` для `:-webkit-autofill`, см. `globals.css`) идёт через `parsePhoneInput` (`+84…`, `84…`, `0…`, `0084…`, пробелы → 9 цифр); номер другой страны (+380…, +7…) не подставляется, поле пустое и подсказка `checkout.phoneForeign`. Адрес, подставленный браузером, — обычный текст без `place_id`, список Google не открывается (подсказки только на набор руками). Кнопки внутри формы — `type="button"`.
Адрес: подсказки Google Places (`AddressField` + `src/lib/places.ts`): от 3 символов, debounce 300 мс, до 5 подсказок, `locationRestriction` — прямоугольник вокруг Дананга (`DANANG_BOUNDS`, тот же в `supabase/functions/_shared/danang.ts`), `includedRegionCodes: ['vn']`, язык ua→en / ru / en / vi, один `sessionToken` на ввод→выбор (Autocomplete → Place Details (New), fields `formattedAddress,location,displayName`). Выбор подставляет «название, адрес» и запоминает `place_id`, `lat`, `lng` (в `submitOrder` уходят как `place_id/lat/lng`); правка текста после выбора сбрасывает координаты; без выбора — обычный текст без координат, заказ не блокируется. Ошибка/квота (403/429) — молча обычное поле, `console.warn`, дальше запросов нет. Под списком «Powered by Google» (требование Google без карты). Проверка ключа с curl: нужен заголовок `Referer: https://ninifoodvn.com/`.
Оплата — три способа: QR (динамический VietQR с суммой «Разом» и назначением, см. ниже), наличные курьеру, «Другой способ» (`other`; UA «Інший спосіб», RU «Другой способ», EN «Other method», VI «Cách khác»). При QR и «Другой способ» **обязательно** скриншот оплаты (jpg/png, компонент `ScreenshotUpload`); перед отправкой он сжимается на клиенте до ~1280px по длинной стороне (JPEG). «Другой способ» — экран `PaymentOther` как QR, но без QR-кода: текст «уточните способ оплаты в Telegram, оплатите и прикрепите скриншот», кнопка «Написать в Telegram» (`settings.telegram_url`, новая вкладка, нажимать необязательно), сводка Обеды / Доставка / Итого, кнопка отправки неактивна без скриншота. Наличные → сразу экран «Спасибо».
**Загрузка скриншота на десктопе** (`ScreenshotUpload`, `useDesktop` в `src/lib/use-desktop.ts`): выбор файла, drag-and-drop в зону (подсветка, «Перетягніть скріншот сюди») и вставка Ctrl/Cmd+V идут через одну проверку `accept` (JPG/PNG/WebP, ≤ 5 МБ, файл должен декодироваться как картинка, иначе понятная ошибка `error.screenshot_type/size`); сжатие до 1280 px JPEG — в `placeOrder`, как раньше. Глобальный `preventDefault` на `dragover/drop` для файлов — `useDropGuard` в `App.tsx` (бросок мимо зоны не открывает картинку). На телефоне зона и тексты прежние.
**VietQR:** `VIETQR` в `src/config/site.ts` (BIDV, счёт 8827465948, получатель LE NU NGOC HA — как на `public/photos/payment-qr.jpg`); `buildQrUrl(amount, note)` → `https://img.vietqr.io/image/BIDV-8827465948-compact2.svg?amount=…&addInfo=…&accountName=…` (svg: png-адрес сервис теперь редиректит на svg; CORS `*`, поэтому CSP `img-src` и `connect-src` содержат `img.vietqr.io`). Назначение платежа — `paymentNote` (`src/lib/payment-note.ts`, копия в `supabase/functions/_shared/payment-note.ts`): «NINIFOOD» + ник Telegram без @ (или последние 4 цифры телефона), только латиница/цифры, ≤ 25 символов; та же строка «🧾 Назначение: …» уходит в сообщение заказа в Orders при QR. `src/lib/qr-image.ts`: при открытии экрана оплаты SVG от vietqr сразу рисуется в PNG 1080 px (canvas, белый фон; QR, сумма и получатель уже в картинке), и на экране показывается этот PNG (blob) — долгое нажатие на iPhone предлагает «Добавить в Фото». Не получилось (сеть/сервис) — статичный `payment-qr.jpg`. «Зберегти QR» (неактивна, пока PNG не готов): на телефонах (`pointer: coarse` + `navigator.canShare({files})`) вызывает `navigator.share({files:[png]})` синхронно по нажатию (иначе iOS блокирует; в меню «Сохранить изображение»), иначе скачивает PNG через `<a download>`. Дат в меню нет. `weight_label` — `450` (г), `150+` (г мяса + гарнир), `2pc` (шт); единицы и подписи КБЖУ (примерные, «≈») подставляет фронт из i18n. Функция `my_discount()` — процент текущего пользователя.

- `order_days` (id, order_id, delivery_date, qty, delivered bool).
- `admins` (user_id) + функция `is_admin()`.

Сводка: активные, порции на завтра из confirmed-подписок, заканчивающиеся (плитка — фильтр). Карточка: Telegram и телефон ссылками, адрес копируется, порций/день, оплата, статус, «доставлено N из M» + полоска, следующая доставка, последний день, точки по дням (зелёная — доставлено, серая — впереди, красная — дата прошла без отметки). Нажатие раскрывает общую карточку заказа `OrderCard.tsx` (её же использует вкладка «Заказы»): все поля, ручная смена статуса, отметка доставки по дням (`order_days.delivered`; триггер БД сам ставит заказу `delivered`), удаление.
- **Заказы**: фильтр по дате доставки и статусу, карточка со всеми полями и днями (скидка: «скидка N%: −X», «обеды» показываются до скидки), ссылка на сообщение в группе (`orderMessageUrl`, `ORDERS_CHAT_ID` — константа в `src/config/site.ts`), заказы с `tg_message_id = null` выделены красным «не дошёл в Telegram», ручная смена статуса (сообщение в Telegram при этом не редактируется), удаление заказа («Удалить заказ» → ввести номер заказа): edge-функция `delete-order` проверяет, что вызывает админ (`is_admin()` по JWT), удаляет заказ с `order_days` каскадом и правит сообщение в группе Orders («🗑 Заказ … удалён из админки», кнопки убраны); если Telegram не принял правку — заказ всё равно удалён, админке показывается предупреждение.
- **Язык:** все строки админки, включая ошибки, — на русском. Ошибки Supabase/сети проходят через `ruError()` (`src/lib/admin/errors.ts`), оригинал — в консоль. Статусы: Новый, Подтверждён, Доставлен, Отменён.
- **Меню**: редактирование недельного шаблона — 6 вкладок Пн–Сб, 4 блюда (суп, горячее, салат, десерт) × 4 языка + описание + вес + КБЖУ + `photo_url` (загрузка фото позже); выбора даты и копирования нет; предупреждение, если у какого-то дня недели меньше 4 блюд.
- **Касса**: форма добавления (приход/расход, дата — по умолчанию сегодня, категория, сумма, комментарий), список за период (сегодня/неделя/месяц/свой, фильтр по типу), итоги, изменение и удаление записи (удаление — вторым нажатием).
- **Деньги**: период (сегодня / неделя / месяц / свой) по дате создания заказа; выручка по confirmed + delivered (после скидок: `orders.total` уже со скидкой; отдельной строкой «Скидки: X ₫», `Bucket.discount`), разбивка наличные / QR / другой способ, разовые / подписки, число заказов и порций. Расчёт — чистые функции `computeRevenue` и `computeProfit` в `src/lib/admin/money.ts`: прибыль = выручка с заказов + ручной приход − расход, плюс разбивка расходов по категориям (себестоимость добавится позже ещё одним вычитаемым). Выручка — по дате создания заказа, касса — по дате операции.
- **Настройки → VIP-клиенты** (`VipCard.tsx`): список (email, заметка), добавить по email (нижний регистр), удалить вторым нажатием.
- **Настройки**: цены обеда и подписки, доставка (за каждый день доставки), ссылка Telegram. Сайт берёт цены и ссылку из публичных строк `settings` (`src/lib/site-settings.ts`), константы в `config/site.ts` — только запасные значения.

## Почта: Resend (сброс пароля по коду) — на потом
Сейчас встроенная почта Supabase: лимит ~2 письма/час, на Free только адреса из команды проекта и нельзя менять шаблон — поэтому сброс выключен (`MAIL_READY` не задан). Чтобы включить:
1. Регистрация на resend.com → Domains → Add Domain `ninifoodvn.com` (регион — ближайший, например Singapore) → в GoDaddy (DNS) добавить записи, которые покажет Resend (SPF `TXT`, DKIM `TXT`/`CNAME`, MX для `send`-поддомена), дождаться статуса Verified.
2. Resend → API Keys → Create (Sending access, домен `ninifoodvn.com`). Ключ — только в менеджер паролей/временный файл, не в чат и не в репозиторий.
3. Supabase → Authentication → Emails → SMTP Settings → Enable custom SMTP: host `smtp.resend.com`, port `465`, user `resend`, password = API-ключ, sender `no-reply@ninifoodvn.com`, name `NiniFood`. Лимит писем потом поднять в Authentication → Rate Limits.
4. Шаблон recovery (Management API `PATCH /v1/projects/<ref>/config/auth`, поля `mailer_subjects_recovery`, `mailer_templates_recovery_content`, UA+EN, с `{{ .Token }}` вместо ссылки; файл `supabase/email-templates/recovery.html`; тема `NiniFood: код відновлення пароля / password reset code`; 6-значный код — `mailer_otp_length: 6` уже выставлен).
5. `MAIL_READY=1` в секреты Supabase (через `--env-file`), проверить «Забули пароль?» с чужим адресом (не из команды).

## Безопасность и бэкапы
- **Секреты:** gitleaks-проверка staged-файлов в `.githooks/pre-commit` (включается `npm install` → `prepare` → `git config core.hooksPath .githooks`; нужен `brew install gitleaks`); разрешённые публичные ключи (anon JWT Supabase, ключ Google Places) — в `.gitleaks.toml`. GitHub: secret scanning + push protection, Dependabot alerts и security updates включены, `main` защищена от force-push и удаления (прямой push разрешён). Новый секрет — только в секреты Supabase / GitHub Actions, значение не в командах и не в файлах проекта (для `supabase secrets set` — временный файл `~/.ninifood/*.env` с chmod 600 и `--env-file`, потом удалить).
- **БД:** RLS на всех таблицах; anon читает только `menu_dishes` и публичные `settings`; `order_attempts` и `security_alerts` — без политик (только service role); `security definer`-функции с `set search_path`; `is_admin()` недоступна ролям anon/PUBLIC. Проверка: `supabase db advisors --linked --type all`.
- **Бэкапы** (`.github/workflows/backup.yml`, раз в сутки 02:17 Дананг + запуск вручную): `pg_dump` (схема `public` целиком + данные `auth.users/identities/mfa_factors`) → шифрование `age` (публичный ключ `backup/age-recipient.txt`) → файл `backups/ninifood-<дата>.tar.age` в **приватном** репозитории `KyryloLushchan/ninifood-backups` (хранятся последние 30). Секреты Actions репозитория `ninifood`: `BACKUP_DB_URL` (строка Session pooler, порт 5432, из Supabase → Connect), `BACKUP_REPO_TOKEN` (fine-grained PAT, Contents: Read and write только на `ninifood-backups`). Приватный ключ age — только у владельца (менеджер паролей), в репозитории и на диске его нет. Если репозиторий 60 дней без коммитов, GitHub отключает расписание — коммиты в `main` его поддерживают.
- **Восстановление:** (1) скачать нужный `.tar.age` из `ninifood-backups`; (2) `age -d -i age-key.txt ninifood-<дата>.tar.age | tar -x -C restore/` → `public.sql` и `auth-data.sql`; (3) новый проект Supabase (регион ap-northeast-2): создать пользователя админа в Auth (или залить `auth-data.sql` в чистую схему `auth` через `psql`), затем `psql "$DB_URL" -f restore/public.sql` (схема + данные, в т.ч. `admins`); (4) заново применить миграции только если восстанавливались данные без схемы: `supabase db push`; (5) расписание cron и Vault не входят в дамп: повторить миграции `daily_report_cron` / `order_attempts` и `vault.create_secret('<CRON_SECRET>', 'cron_secret')`; (6) заново задать секреты функций (`TELEGRAM_BOT_TOKEN`, `TG_WEBHOOK_SECRET`, `ORDERS_CHAT_ID`, `ADMIN_TG_IDS`, `CRON_SECRET`, `TURNSTILE_SECRET`, `IP_HASH_SALT`), задеплоить функции, перерегистрировать вебхук бота (`setWebhook`). Процедура ни разу не прогонялась на чистом проекте — при первой возможности проверить на тестовом.
